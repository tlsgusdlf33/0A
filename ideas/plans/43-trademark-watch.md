# 43. 소상공인 상표 감시 & 이의신청 기한 알림

> **병합 제안 (2026-10-17)**: 10번(소상공인 리뷰 답글 SaaS)의 부가 구독 모듈로 붙이는 것을 권장합니다. 같은 고객(사장님)·같은 결제·같은 영업 채널(42번 신규 개업 리드)을 공유합니다. KIPRIS 수집기는 G7(31번 kit)의 공공 API 클라이언트 규격으로 만들어 재사용합니다. 사용자가 병합을 지시하면 10번 세션으로 전달합니다.

## 최종 목표
- **등록한 상호·브랜드와 유사한 상표 출원을 출원공고 후 7일 안에 100% 알림** (이의신청 기한 2개월을 놓치는 일 0건)
- 12개월 안에 유료 구독 50곳 (월 4,900원 부가 요금 기준 월 약 25만 원)
- 내 프로젝트 브랜드(7·30·39번 판매 사이트, A20·A21·A22 작품·채널명 등)도 같은 감시 대상에 넣어 보호
- 운영은 주 1시간 이하

## MVP 범위
- 감시 대상 등록: 상호(한글·영문), 대표 문구, 업종 → 상품 분류(니스 류) 자동 추천
- 매일 신규 출원·출원공고 수집 → 유사도 점수 → 기준 이상만 알림
- 알림 내용: 출원인, 출원 상표, 지정상품 류, 출원공고일, **이의신청 마감일**, KIPRIS 원문 링크
- 마감 D-30·D-7 리마인드, "변리사 상담 권장" 안내 문구

## 기술 구조
- 데이터: KIPRIS Plus 상표 검색·공보 API (이용 신청, 호출 한도·요금 0단계에서 확인)
- 유사도:
  - 표기: 정규화(띄어쓰기·특수문자 제거) 후 편집거리, 영문↔한글 음역 비교
  - 발음: 한글 자모 분해 후 발음 유사도(초성·모음 가중치)
  - 지정상품: 같은 류 또는 유사군 코드가 겹칠 때 가중치
  - 점수 상위 후보만 LLM으로 "혼동 가능성 근거" 1~2줄 작성 (판단이 아니라 참고 설명)
- 저장: SQLite(단독) 또는 10번 DB의 별도 스키마(병합 시)
- 알림: 텔레그램·이메일, 10번에 병합 시 사장님 앱 알림
- 배포: 병합 시 10번 웹앱의 메뉴 1개. 단독일 경우 사용자 선호 방식(안드로이드 APK, Termux 없이, 앱 내 업데이트)
- 비용: API 이용료(확인 필요) + LLM은 상위 후보에만

## 단계별 절차
| 단계 | 할 일 | 완료 기준 |
|---|---|---|
| 0. API 확인 | KIPRIS Plus 이용 신청, 제공 필드(출원공고일·지정상품·유사군 코드)와 갱신 주기·요금 확인 | 필요한 필드가 모두 API로 제공됨을 확인 |
| 1. 수집기 | 31번 kit 규격으로 일일 신규 출원·공고 수집, 스키마 검증, 실패 이벤트 전송 | 30일치 백필 + 매일 자동 수집 |
| 2. 유사도 엔진 | 표기·발음·류 점수, 테스트 세트(실제 이의신청·거절 사례 50건)로 기준값 조정 | 테스트 세트 재현율 90% 이상, 대상당 주간 알림 3건 이하 |
| 3. 알림·기한 | 이의신청 마감일 계산(출원공고일 + 2개월), D-30·D-7 알림 | 샘플 대상 5개로 2주간 정상 발송 |
| 4. 등록 화면 | 상호 입력 → 류 추천 → 감시 시작, 알림 기록 화면 | 등록 1분 이내 |
| 5. 10번 연동(병합 시) | 10번 가게 프로필에서 상호 자동 불러오기, 구독 옵션·결제 추가 | 10번 사용자가 클릭 1번으로 가입 |
| 6. 내 브랜드 보호 | 7·30·39번, A20~A22 작품·채널명을 감시 목록에 등록 | 내 브랜드 감시 자동 운영 |
| 7. 판매 | 10번 고객·42번 신규 개업 리드에 안내, 무료 1개월 | 유료 구독 10곳 |
| 8. 운영 자동화 | 26번 운영 대시보드 연동, 월간 리포트 | 30일 무개입 운영 |

## 법·정책 주의사항
- 이 서비스는 **정보 제공**이며 상표 유사 여부 판단·이의신청 대리는 변리사 업무 → 화면·약관에 명시, 법률 판단 표현 금지
- KIPRIS 데이터 이용 조건(상업적 이용·재배포)과 출처 표시 확인
- 출원인 정보 중 개인 출원인 이름·주소는 화면에 최소한으로만 표시

## 리스크와 대응
- 오탐이 많으면 해지 → 기준을 보수적으로, 사용자가 "관련 없음" 표시하면 비슷한 후보 자동 제외
- API 요금·한도 변경 → 수집을 하루 1회 일괄 처리로 호출 수 최소화
- 수요 검증 부족 → 10번 고객 대상 무료 체험으로 먼저 반응 확인

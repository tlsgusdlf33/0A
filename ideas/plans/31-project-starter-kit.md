# 31. 프로젝트 공통 스타터킷 & 보안 가드레일

## 최종 목표
- **새 프로젝트 생성부터 첫 수집·첫 알림 동작까지 1시간 이내**
- 민감정보(비밀키, 주민등록번호·카드번호 패턴, 금융·의료 데이터 파일) **커밋 사고 0건**: 로컬과 CI 양쪽에서 차단
- 앞으로 시작하는 프로젝트는 100% 템플릿으로 생성, 이미 시작한 프로젝트는 3개월 안에 절반 이상 공통 모듈로 전환
- 공통 모듈이 개선되면 각 프로젝트에 업데이트 PR이 자동으로 생성됨

## 구성 요소
### 1) 공통 패키지 (`kit`)
| 모듈 | 역할 | 쓰는 프로젝트 예 |
|---|---|---|
| config | 연도별 YAML 설정(세법·한도 수치) + 환경변수 비밀값 로딩, 출처 메모 필드 | 12, 17, 23, 25, 28, 32 |
| http | 재시도·백오프·호출 한도, 공공데이터포털 인증키·XML/JSON 응답 처리, **응답 형식 검증(스키마) 실패 시 26번에 이벤트 전송 (34번 병합)** | 1, 17, 19, 20, 27, 29 |
| storage | SQLite 헬퍼, 스키마 마이그레이션, 일별 스냅샷 | 거의 전부 |
| notify | 텔레그램 알림(심각도·묶음·조용한 시간), 승인 버튼 | 4, 17, 19, 25, 33 |
| ops | 26번 운영 연동 표준(하트비트·이벤트·헬스체크) 클라이언트 | 전부 |
| llm | 구조화 추출(스키마 검증·재시도), 결과 캐시, 호출 비용 기록 → 26번 | 10, 18, 20, 21, 24, 33 |
| privacy | 주민번호·계좌번호·카드번호 마스킹, 이미지 EXIF·위치정보 제거 | 13, 18, 21, 24 |
| rules | **세법·제도 수치 레지스트리 (35번 병합)**: 연도별 공제 한도·세율·기준 금액을 출처와 함께 한 곳에서 관리, 각 프로젝트는 여기서 읽음 | 12, 17, 23, 25, 28, 32, 36 |

### 2) 템플릿 레포
- Python 프로젝트 구조(pyproject, 테스트 폴더), 선택형 TypeScript(Cloudflare Workers) 폴더
- `CLAUDE.md` 개발 규칙: 민감 데이터 처리 원칙, 세법·한도 수치는 설정 파일로, 공식 API만 사용·약관 확인, 테스트 필수, 26번 연동 필수 → **다른 Claude Code 세션이 처음부터 같은 규칙으로 개발**
- 크론 예시(GitHub Actions, 한국 시간 주석), `.gitignore`(data/, *.db, 영수증·명세서 폴더)

### 3) 보안 가드레일
- 로컬: pre-commit 훅
- CI: 비밀키 스캔(gitleaks 등) + **한국 개인정보 사용자 규칙**(주민등록번호는 검증 숫자까지 확인해 오탐 감소, 카드번호는 Luhn 검사), 금지 경로·확장자 차단, 의존성 취약점 점검, 린트·테스트
- 오탐은 허용 목록 파일로 관리 (실제 개인 데이터를 테스트 데이터로 쓰는 것은 금지, 가짜 데이터 생성기 제공)

### 4) 세법·제도 수치 레지스트리와 변경 감지 (35번 병합)
- 수치는 `kit/rules/<연도>.yaml` 한 곳에만 두고, 항목마다 출처 링크·시행일 기록 (각 프로젝트가 따로 복사하지 않음)
- 변경 감지 작업(주 1회): 법령 개정 Open API, 국세청·기재부 보도자료 수집 → 바뀐 수치 후보 추출(LLM은 후보 추출만, 숫자는 원문 대조) → 레지스트리 수정 PR 생성(근거 링크, 개정안·통과·시행 단계 표시)
- 사용자가 PR을 승인하면 아래 업데이트 전파로 모든 프로젝트에 반영

### 5) 업데이트 전파
- `kit`에 버전 태그 → 각 프로젝트에 의존성 업데이트 PR 자동 생성 (Dependabot·Renovate 또는 자체 Action)

## 단계별 절차
| 단계 | 할 일 | 완료 기준 |
|---|---|---|
| 0. 공통 코드 조사 | 이미 개발 중인 프로젝트 2~3개에서 반복된 코드 목록화 | 모듈 후보 표 |
| 1. kit 핵심 모듈 | config, http, storage, notify, ops 먼저 + 테스트 | 테스트 커버리지 80% 이상 |
| 2. 템플릿 레포 | 프로젝트 구조, `CLAUDE.md`, 크론 예시, `.gitignore` | 템플릿으로 새 레포 생성 가능 |
| 3. 보안 가드레일 | pre-commit + CI 규칙, 가짜 개인정보로 차단 테스트 | 가짜 주민번호·카드번호·비밀키·db 파일 커밋이 모두 차단 |
| 4. 파일럿 | 아직 시작 안 한 채택 프로젝트 1개(예: 17 또는 29)를 템플릿으로 시작 | 첫 알림까지 1시간 이내 |
| 5. 나머지 모듈 | llm, privacy 모듈 추가 | 18·24번 같은 문서 추출 프로젝트에 적용 |
| 6. 기존 프로젝트 전환 | 이미 시작한 프로젝트 2개를 공통 모듈로 교체 | 기능 동일, 코드량 감소 |
| 7. 업데이트 전파 | kit 버전 태그 → 자동 PR | 한 번의 수정이 모든 레포에 PR로 도착 |
| 8. 문서·유지보수 | 모듈별 사용 예제, 분기마다 의존성 업데이트 | 새 세션이 문서만 보고 사용 가능 |
| 9. 응답 형식 검증 (34번 병합) | http 모듈에 API별 응답 스키마 정의·검증, 실패 시 26번 이벤트 | 응답 필드 변경을 테스트로 재현했을 때 이벤트 발생 |
| 10. 수치 레지스트리 (35번 병합) | 12·23·25·28·32·36번이 쓰는 세법 수치를 `rules`로 이전, 변경 감지 작업 + 수정 PR 자동 생성 | 수치 1개를 바꾼 테스트 보도자료로 PR 생성, 승인 후 모든 프로젝트에 업데이트 PR 도착 |

## 주의사항
- `kit` 저장소는 비공개로 유지하거나, 공개할 경우 비밀값·개인 설정이 전혀 없도록 분리
- 가드레일은 실수 방지 장치일 뿐: 민감 데이터는 처음부터 레포 밖(로컬·비밀 저장소)에 두는 원칙 유지

## 리스크와 대응
- 공통 모듈 변경이 여러 프로젝트를 한꺼번에 깨뜨림 → 버전 고정 + 자동 PR에서 각 프로젝트 테스트 통과 후 머지
- 오탐으로 커밋이 자주 막힘 → 검증 숫자·Luhn 검사로 오탐을 줄이고 허용 목록 운영
- 과도한 추상화 → 2개 이상 프로젝트에서 실제로 반복된 코드만 모듈로 올림

# 44. 나라장터 소규모 용역 입찰 매칭 + 제안서 초안

> **병합 제안 (2026-10-17)**: 20번(정부 창업·지원사업 자동 매칭)에 병합하는 것을 권장합니다. "공고 수집 → 자격 조건 구조화 → 내 프로필과 매칭 → 마감 알림·제출서류 체크리스트" 엔진이 같고, 20번은 이미 안드로이드 APK(Termux 없이)로 동작합니다. 공고 출처에 나라장터를 추가하고 "제안서 초안" 기능을 더하는 형태입니다. 사용자가 병합을 지시하면 20번 세션으로 전달합니다.
> 개인 세션 참고: 사용자는 건설기계 기술사(A3)·2D 도면 3D 모델링(A6) 작업을 하고 있어, SW·디자인 용역뿐 아니라 **건설기계·설계·엔지니어링 분야 소규모 용역**도 매칭 대상에 포함합니다.

## 최종 목표
- **참여 가능한 소규모 용역 공고를 놓치는 일 0건** (조건에 맞는 공고는 게시 24시간 안에 알림)
- 12개월 안에 견적·입찰 10건 참여, 수주 2건 이상 (부업 용역 수익)
- 공고 1건 검토 + 제안서 초안 확보까지 **30분 이하**

## MVP 범위
- 나라장터 입찰공고(용역) 매일 수집
- 필터: 추정가격 상한, 지역 제한, 참가자격(업종 코드·면허), 실적 요건, 소기업·1인 참여 가능 여부, 수의계약·소액 견적 여부
- 적합도 점수: 내 실적·기술(채택 프로젝트, 개인 프로젝트, 자격·경력)과 과업 내용 비교
- 알림: 새 매칭 공고 즉시, 마감 D-7·D-2, 제출서류 체크리스트
- 제안서 초안: 과업 이해, 수행 방안, 일정, 투입 인력, 유사 실적 목록 (사람이 검토 후 제출)

## 기술 구조
- 데이터: 조달청 나라장터 입찰공고정보 서비스(공공데이터포털 Open API), 필요 시 사전규격 공개 정보 → 0단계에서 필드·갱신 주기 확인
- 첨부 공고문·과업지시서(HWP·PDF): 텍스트 추출 → LLM으로 자격 요건·과업 범위 구조화 (20번의 자격 구조화 프롬프트 재사용)
- 내 프로필: 20번 프로필에 항목 추가 (사업자 업종 코드, 직접생산확인 여부, 실적 목록, 보유 자격, 포트폴리오 링크)
- 제안서 초안: 과업지시서 + 실적 목록 → 목차별 초안(Markdown → HWPX·DOCX 내보내기)
- 저장·알림·배포: 20번과 동일 (SQLite, 텔레그램·앱 알림, 안드로이드 APK + 앱 내 업데이트)
- 비용: 거의 0원 (LLM은 매칭 상위 공고와 제안서 작성 시에만)

## 단계별 절차
| 단계 | 할 일 | 완료 기준 |
|---|---|---|
| 0. 자격 준비 확인 | 조달청 경쟁입찰 참가자격 등록 절차, 사업자 업종 코드, 직접생산확인 필요 분야 정리 | 내가 지금 참여 가능한 공고 유형 목록 |
| 1. API·수집 | 나라장터 용역 공고 API 연동, 지난 3개월 백필 | 일일 자동 수집, 누락 없음 |
| 2. 조건 필터 | 금액·지역·자격·실적·소기업 제한 필터, "참여 가능 / 확인 필요 / 불가" 판정 | 표본 50건 수동 판정과 일치율 90% |
| 3. 적합도 점수 | 과업 키워드와 내 실적·기술 비교, SW·디자인·건설기계·설계 분야 가중치 | 상위 10건 중 7건 이상이 실제로 관심 있는 공고 |
| 4. 알림·체크리스트 | 새 공고·마감 알림, 제출서류 체크리스트(20번 화면 재사용) | 2주간 정상 발송 |
| 5. 제안서 초안 | 과업지시서 기반 목차 초안 + 실적 표, HWPX·DOCX 내보내기 | 초안 수정 시간 30분 이하 |
| 6. 결과 기록 | 참여·낙찰 결과와 낙찰가 수집 → 다음 견적가 참고값 | 참여 공고별 결과 자동 기록 |
| 7. 확장 | 지자체·공공기관 자체 소액 견적 공고, 사전규격 공개 단계 알림 | 출처 2곳 이상 추가 |

## 법·정책 주의사항
- 입찰 참가자격·서류 제출은 본인이 직접. 자동 제출·자동 투찰은 만들지 않음
- 제안서에 허위 실적·경력 금지: 초안은 등록된 실제 실적만 사용
- 재직 중이라면 겸업 규정 확인 (회사 취업규칙)
- 공공데이터 이용 조건과 출처 표시 확인

## 리스크와 대응
- 실적 요건 때문에 초기 참여가 어려움 → 실적 요건 없는 소액 수의계약·견적부터, 채택 프로젝트 결과물을 실적으로 정리
- 첨부 HWP 해석 오류 → 원문 링크 함께 제공, "확인 필요" 판정으로 보수적으로 분류
- 업무량 과다 → 동시에 진행할 수주 건수 상한 설정

# 39. 한국 결제·인증 연동 SaaS 보일러플레이트 판매

> **통합 묶음 G6 판매 인프라 주 프로젝트 (2026-10-16)**: 39 + 7 + 30번을 이 세션에서 하나로 개발합니다. 흡수된 프로젝트의 계획: `07-digital-template-shop.md`, `30-custom-poster-pod.md`. 묶음 설명은 `ideas/synergy-groups.md`.

## 최종 목표
- **12개월 안에 판매 50건, 누적 매출 1,000만 원**
- 이 코드로 새 웹 서비스를 시작할 때 결제·로그인·법적 고지까지 붙이는 시간 **며칠 → 1시간**
- 분기 1회 이상 업데이트(SDK·법령 변경 반영), 환불률 5% 이하
- 판매·접근 권한 부여·업데이트 배포까지 사람 손 0

## 핵심 전략: 직접 쓰면서 만든다
10번(리뷰 답글 SaaS)과 30번(포스터 판매)을 만들 때 결제·로그인 부분을 처음부터 **분리 가능한 모듈**로 짜고, 실제 운영에서 검증된 코드를 상품으로 묶습니다. 판매 사이트 자체도 이 보일러플레이트로 만들어서 데모로 씁니다.

## 구성 요소
| 모듈 | 내용 |
|---|---|
| 인증 | 카카오·네이버·구글 로그인, 이메일 로그인, 세션·권한 |
| 본인인증 | 본인확인 서비스 연동 어댑터 (계약이 필요한 서비스라 테스트 모드 + 연동 가이드 제공) |
| 결제 | 국내 PG 단건 결제·정기결제(빌링), 웹훅 서명 검증, 환불·부분취소, 결제 연동 플랫폼 어댑터(선택) |
| 구독 관리 | 무료 체험 → 유료 → 결제 실패 → 해지 상태 관리, 재시도·안내 메일 |
| 법적 고지 템플릿 | 개인정보처리방침, 이용약관, 사업자 정보 표시, 정기결제·청약철회 사전 고지 문구 (법률 자문 아님 명시) |
| 알림 | 이메일, (선택) 알림톡 발송 서비스 어댑터 |
| 관리자 | 사용자·결제·구독 관리 화면 |
| 운영 | 26번 운영 연동, 31번 보안 가드레일 기본 탑재 |

## 기술 구조
- Next.js + TypeScript, DB는 Postgres(Supabase 등), 모듈별 폴더로 분리해 필요 없는 모듈은 지울 수 있게
- 테스트: PG·로그인 테스트 키로 결제·정기결제·환불·웹훅 전 과정 E2E 테스트 자동화
- 판매 자동화: 결제 완료 웹훅 → GitHub API로 비공개 레포 접근 권한 부여 + 라이선스 키 발급 → 환불 시 권한 자동 회수
- 업데이트: 비공개 레포 릴리스 노트 + 구매자 메일 알림
- 비용: 호스팅 소액, PG 수수료 별도

## 단계별 절차
| 단계 | 할 일 | 완료 기준 |
|---|---|---|
| 0. 수요 확인 | 개발 커뮤니티의 결제·로그인 연동 질문 빈도, 해외 보일러플레이트 가격대 조사, 사전 알림 신청 페이지 | 사전 신청 30명 |
| 1. 모듈 분리 개발 | 10번 또는 30번 개발 때 인증·결제를 독립 모듈로 작성 | 실제 서비스 1곳에서 운영 중 |
| 2. 결제 모듈 완성 | 단건·정기결제·환불·웹훅, 테스트 키 E2E 테스트 | E2E 테스트 전부 통과 |
| 3. 인증·본인인증 | 소셜 로그인 3종 + 본인인증 어댑터(테스트 모드) | 새 프로젝트에 30분 안에 적용 |
| 4. 법적 고지 템플릿 | 페이지 템플릿 + 결제 화면 고지 문구, 가능하면 전문가 검토 | 템플릿 완성, "자문 아님" 고지 |
| 5. 문서·데모 | 설치 가이드, 모듈 설명, 판매 사이트 겸 데모 | 처음 쓰는 개발자가 1시간 안에 결제까지 동작 |
| 6. 판매 자동화 | 결제 → 레포 권한·라이선스 → 환불 시 회수 | 테스트 구매 무인 처리 |
| 7. 출시 | 사전 신청자 할인, 개발 커뮤니티에 제작기 공유 | 첫 10건 판매 |
| 8. 유지보수 | PG·로그인 SDK 변경 감시, 분기 업데이트, 구매자 피드백 반영 | 12개월 50건 |

## 법·정책 주의사항
- 라이선스: 구매자 프로젝트 사용 허용, 코드 자체 재판매·공개 배포 금지 조항
- 템플릿에 **실제 API 키·비밀값 절대 포함 금지** (31번 가드레일로 차단), 테스트 키만
- 법적 고지 템플릿은 출발점일 뿐이며 서비스별 검토 필요하다고 명시
- 오픈소스 의존성 라이선스 호환 확인
- 판매자로서 사업자 등록·통신판매업 신고, 회사 겸업 규정 확인

## 리스크와 대응
- PG·로그인 SDK 변경으로 코드가 깨짐 → E2E 테스트를 매주 자동 실행해 먼저 감지
- 무료 예제와 경쟁 → 실제 운영 검증, 구독 상태 관리·법적 고지까지 포함한 완성도로 차별화
- 지원 요청 과다 → 문서·FAQ 우선, 지원 범위를 판매 페이지에 명시

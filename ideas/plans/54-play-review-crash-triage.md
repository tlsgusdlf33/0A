# 54. 내 앱 플레이 리뷰·비정상 종료 자동 분류 & 답글·수정 이슈 생성

> **49번 보완 (2026-10-23 갱신)**: 49번이 단독 프로젝트로 확정되어, 이 기능은 49번의 "출시 후" 단계(49번 계획 9단계)로 붙이는 것을 제안합니다. 같은 서비스 계정·같은 웹 대시보드를 사용합니다. 리뷰 답글 초안은 10번(리뷰 답글 SaaS)의 말투 맞춤 답글 엔진을 재사용할 수 있습니다.

## 최종 목표
- 사용자 안드로이드 앱 전체의 새 리뷰·비정상 종료·ANR(앱 멈춤)을 **24시간 안에 100% 수집·분류**
- 리뷰 답글 응답률 **90% 이상**, 답글 1건 처리 시간 10초 이하 (초안 승인)
- 비정상 종료 상위 원인은 **자동으로 수정 이슈 생성** → 안정성 지표(비정상 종료율) Play 기준치 이하 유지
- 주간 리포트 확인 시간 5분

## MVP 범위
- 수집: 앱별 새 리뷰(별점·내용·기기·앱 버전), 비정상 종료·ANR 집계와 스택 정보
- 분류: 리뷰를 버그·기능 요청·광고 불만·칭찬·기타로, 비정상 종료를 스택 패턴별로 묶기
- 답글: 리뷰별 한국어 답글 초안(앱별 말투 설정) → 텔레그램/앱에서 승인 → 게시
- 이슈: 같은 원인 비정상 종료가 기준 이상이면 해당 레포에 이슈 자동 생성(스택·영향 사용자 수·발생 버전), 중복 방지
- 리포트: 앱별 평점 추이, 비정상 종료율·ANR율, 새 버전 출시 전후 비교(49번 출시 이벤트와 연결)

## 기술 구조
- Google Play Developer API: 리뷰 조회·답글 게시(reviews), Play Developer Reporting API: 비정상 종료율·ANR율·오류 클러스터
- 서비스 계정: 49번과 같은 계정(앱별 최소 권한: 리뷰 답글 + 보고서 조회)
- 분류·답글: LLM (분류는 규칙 + LLM, 답글은 10번 답글 엔진 프롬프트 재사용)
- 이슈 생성: GitHub API, 앱 ↔ 레포 매핑은 49번 `release.yml`에 추가
- 실행: 매일 1회 배치(GitHub Actions 예약), 알림은 31번 kit 텔레그램
- 리포트: 49번 웹 대시보드에 평점·안정성 화면 추가 (26번 운영 대시보드에는 지표만 전송 가능)

## 단계별 절차
| 단계 | 할 일 | 완료 기준 |
|---|---|---|
| 0. 권한·데이터 확인 | 리뷰·보고서 API 권한 부여, 앱별 데이터 제공 범위 확인 (리뷰는 최근 기간만 조회되는 제약 확인) | 시험 앱(A9 주말나들이) 리뷰·지표 조회 성공 |
| 1. 수집 | 앱별 일일 수집, 중복 제거, 저장 | 7일 연속 누락 0건 |
| 2. 분류 | 리뷰 5분류, 비정상 종료 스택 묶기 | 표본 50건 수동 분류와 일치율 85% |
| 3. 답글 | 앱별 말투 설정, 초안 → 승인 → 게시 | 승인부터 게시까지 10초 |
| 4. 이슈 자동 생성 | 기준 이상 비정상 종료 → 레포 이슈, 중복 방지 | 테스트 오류로 이슈 1건만 생성 |
| 5. 리포트 | 평점·안정성 추이, 출시 전후 비교 | 주간 리포트 자동 발송 |
| 6. 전 앱 적용 | 49번 파이프라인 사용 앱 전체 등록 | 앱 6개 이상 |

## 법·정책 주의사항
- Google Play 리뷰 답글 정책 준수: 사람이 승인한 답글만 게시, 개인정보 요청·보상 약속 금지
- 리뷰 작성자 이름 등 개인정보는 이슈·리포트에 넣지 않음
- 서비스 계정 키는 비밀 저장소에만, 최소 권한

## 리스크와 대응
- 리뷰 수가 적은 초기 앱 → 테스터 피드백도 같은 분류로 함께 관리
- 자동 답글이 어색하거나 부적절 → 항상 사람 승인, 금지 표현 목록
- 이슈 과다 생성 → 원인별 묶기·발생 기준값·주 1회 요약 이슈 옵션

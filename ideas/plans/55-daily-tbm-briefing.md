# 55. 매일 작업 전 안전점검회의(TBM) 자료 자동 생성

> **46번 보완 제안 (2026-10-24)**: 46번(차량계 건설기계 작업계획서·위험성평가)에 입력된 장비·작업 정보를 그대로 써서 매일 아침 자료를 만듭니다. 46번 앱의 "오늘" 탭으로 넣는 것을 권장합니다. 46·47·51·52번과 함께 "건설기계 실무 도구" 묶음(가칭 G8) 후보입니다. 사용자가 병합을 지시하기 전까지는 46번과 같은 레포의 별도 모듈로 진행합니다.

## 최종 목표
- 현장 관리자가 TBM 자료 준비에 쓰는 시간 **매일 20분 → 1분** (아침 알림 확인 → 출력 또는 화면 공유)
- 그날 작업·장비·날씨에 맞지 않는 일반 문구 대신 **오늘 위험 3가지가 매일 달라지는** 자료 (같은 내용 3일 연속 반복 0회)
- 참석자 서명 기록 누락 0건 (중대재해처벌법 대응용 이행 증빙)
- 46번 구독 유지율 향상: 매일 쓰는 기능으로 월 이탈률 5% 이하

## MVP 범위
- 입력: 46번 작업계획서(현장 위치, 투입 장비, 작업 종류, 작업 기간) + 그날 변경 사항(장비 추가, 작업 구역 변경) 간단 입력
- 날씨: 기상청 단기예보(현장 좌표 기준) → 강풍(크레인·고소작업 제한 기준), 강우(지반 연약), 폭염·한파(작업자 건강), 미세먼지
- 사고 사례: 안전보건공단 재해사례(공공데이터) 중 같은 기종·작업 유형 사례 1건 요약
- 자료 구성(한 장): 오늘 작업 요약 → 오늘 위험 3가지(장비·작업·날씨) → 대책 → 유사 사고 사례 1건 → 확인 질문 2개 → 참석자 서명란
- 전달: 매일 아침 지정 시각 폰 알림, PDF 출력, 화면에서 바로 낭독용 보기
- 서명: 참석자가 관리자 폰 화면에 서명 또는 명단 체크 → 날짜별 보관

## 기술 구조
- 46번 앱(안드로이드 APK, Termux 없이, 앱 내 업데이트)의 모듈로 구현, PC에서 월별 이행 기록 출력
- 기상청 단기예보 Open API(공공데이터포털), 현장 주소 → 격자 좌표 변환
- 재해사례: 안전보건공단 공공데이터(재해사례·사망사고 속보 등) 수집 → 기종·작업 키워드 분류 → 사례 요약은 LLM, 원문 링크 첨부
- 위험 선택 규칙: 46번 위험 요인 라이브러리 × 오늘 날씨 조건 × 최근 사용 이력(반복 방지)
- 저장: 일자별 자료·서명 기록(폰 로컬 + 클라우드 동기화)

## 단계별 절차
| 단계 | 할 일 | 완료 기준 |
|---|---|---|
| 0. 양식 조사 | 실제 현장 TBM 일지 양식 3종 수집, 필수 기재 항목 정리 | 자료 구성안 확정 |
| 1. 날씨 연동 | 현장 좌표 → 단기예보 수집, 작업 제한 기준(풍속 등) 판정 | 7일간 예보 기반 경고 정상 생성 |
| 2. 재해사례 DB | 공단 사례 수집, 기종·작업 키워드 분류 (굴삭기·크레인·지게차부터) | 사례 300건 분류 |
| 3. 위험 선택 엔진 | 오늘 장비·작업·날씨 → 위험 3가지 + 대책, 반복 방지 | 2주 시뮬레이션에서 3일 연속 반복 0회 |
| 4. 자료 생성 | 한 장 PDF·화면 보기, 확인 질문 2개 | 1분 안에 읽을 수 있는 분량 |
| 5. 알림·서명 | 아침 알림, 참석자 서명·명단 체크, 날짜별 보관 | 서명 기록 누락 0건 |
| 6. 현장 시범 | 직장 현장 2주 사용, 관리자 의견 반영 | 수정 요청 반영 |
| 7. 이행 기록 출력 | 월별 TBM 실시 기록(날짜·참석자·내용) PDF | 감독·점검 시 제출 가능한 형식 |

## 법·정책 주의사항
- 자료는 TBM 진행을 돕는 초안이며 안전관리 책임은 사업주·관리자에게 있음을 명시
- 재해사례는 공공데이터 이용 조건에 따라 출처 표시, 피해자 개인정보는 사용하지 않음
- 참석자 서명·이름은 개인정보 → 수집 동의, 보관 기간 정책

## 리스크와 대응
- 재해사례 분류가 부정확 → 기종 키워드 사전 + 사람이 확인한 사례에 우선순위
- 현장 통신 불량 → 전날 밤 자료 미리 생성·오프라인 저장
- 매일 같은 형식에 따른 형식화 → 확인 질문을 매일 바꾸고 최근 사고 속보 우선 반영

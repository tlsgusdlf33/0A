# 48. 내 웹소설 다국어 번역 전자책 출판 파이프라인

> **A20·A22 보완 제안 (2026-10-19)**: 사용자 개인 세션 A20(소설 수익화)의 원고와 A22(웹툰)의 캐릭터·용어 설정을 재사용합니다. A20 레포에 `translation/` 모듈로 두는 것이 자연스럽습니다. 개인 세션이라 사용자가 지시할 때만 전달합니다.

## 최종 목표
- 완결된 1권(약 20~25화) 분량을 **영어 전자책으로 7일 안에** 출판 패키지까지 완성
- 인명·지명·고유 용어 번역 **불일치 0건** (용어 사전 검사 통과)
- 12개월 안에 영어·일본어 각 3권 출간, 월 로열티 수입 발생 (초기 기대치는 월 수만 원 수준, 시리즈 누적으로 증가)
- 사람이 들이는 시간: 권당 검수 3시간 이하

## MVP 범위
- 입력: A20 완결 회차 원고(Markdown/텍스트), A22 캐릭터 설정
- 용어 사전: 인명·지명·기술명·호칭 → 언어별 고정 번역(사용자 확정)
- 번역: 회차 단위 번역 → 용어 사전 강제 적용 → 문체 일관성 검사(시점·시제·말투)
- 검수 리포트: 사전 위반, 누락 문단, 길이 이상(원문 대비), 어색한 문장 후보
- 출판 패키지: 권 단위 EPUB(목차·표지·저작권 페이지), 스토어 메타데이터(제목·소개문·키워드·분류), 언어별 소개문
- 업로드는 사용자가 직접 (스토어 정책상 자동 업로드 API 없음)

## 기술 구조
- 파이프라인: Python 스크립트 + GitHub Actions(원고 커밋 시 자동 실행), 결과물은 릴리스에 첨부
- 번역: LLM API, 회차별 이전 요약·용어 사전·문체 가이드를 함께 넣어 일관성 유지
- 검사: 용어 사전 정규식 검사, 원문·번역 문단 정렬(문단 수·길이 비교)
- EPUB 생성: pandoc 또는 ebooklib, 표지는 A22 웹툰 일러스트 재사용(권리 확인된 이미지)
- 폰 연동: 검수 리포트를 폰에서 확인·용어 확정 (선호 배포 형태: 안드로이드 APK 또는 웹 뷰)

## 단계별 절차
| 단계 | 할 일 | 완료 기준 |
|---|---|---|
| 0. 권리·정책 확인 | 국내 연재 플랫폼 계약 시 해외·전자책 판권 조항, 해외 전자책 스토어의 AI 번역 표기 정책 확인 | 출판 가능 범위 정리 |
| 1. 용어 사전 | A20 원고·A22 설정에서 고유명사 자동 추출 → 사용자 확정 | 1권 용어 100% 확정 |
| 2. 번역 엔진 | 회차 번역 + 사전 강제 + 이전 회차 요약 컨텍스트 | 1~3화 샘플 사전 위반 0건 |
| 3. 검수 리포트 | 누락·길이 이상·문체 불일치 탐지 | 샘플에서 의도적으로 넣은 오류 100% 검출 |
| 4. EPUB·메타데이터 | 권 단위 EPUB, 표지, 소개문·키워드 | 전자책 검증 도구(EPUBCheck) 통과 |
| 5. 1권 출간 | 영어 1권 검수 → 사용자가 스토어 업로드 | 판매 페이지 공개 |
| 6. 판매 데이터 | 스토어 판매 보고서(CSV) 월 1회 집계, 28번 부업 장부(G1)로 전달 | 월별 로열티 자동 집계 |
| 7. 확장 | 일본어, 후속 권 자동화, 오디오북(A21 음성) 검토 | 언어 2개 × 3권 |

## 법·정책 주의사항
- 해외 전자책 스토어는 AI 생성·AI 번역 콘텐츠 신고를 요구하는 경우가 있음 → 정책에 맞게 표기, 대량 저품질 등록 금지
- 국내 플랫폼 독점 연재·판권 계약이 있으면 해외 출판 전 반드시 확인
- 표지·삽화는 권리가 확인된 이미지(직접 제작·A22 결과물)만 사용
- 해외 로열티는 종합소득세 신고 대상 → 28번 장부와 연동

## 리스크와 대응
- 번역 품질에 따른 낮은 평점 → 1권은 원어민 베타리더 검수(유료 소액) 고려, 리뷰 반영
- 판매량이 작음 → 시리즈 누적·가격 실험(1권 할인)으로 점진 성장 기대
- 플랫폼 정책 변경 → 스토어 2곳 이상 분산

# 49. 안드로이드 앱 공통 출시 파이프라인 (플레이스토어 업로드·실수 방지 가드)

> **31번 보완(병합 제안) (2026-10-19)**: 묶음 G7(주 프로젝트 31번 스타터킷)에 "앱 출시 표준"으로 넣는 것을 권장합니다. 31번 템플릿을 쓰는 모든 안드로이드 프로젝트(1·8·13·20번, 매매신호앱 등)가 같은 워크플로를 가져다 씁니다. 사용자가 병합을 지시하면 31번 세션으로 전달합니다.

## 최종 목표
- 업데이트 출시 1건에 드는 사람 손 작업을 **30분 이상 → 3분 이하** (태그 푸시 → 자동 업로드 → 승인 1번)
- 출시 실수(테스트 광고 ID로 정식 출시, 실제 광고 ID로 테스트 배포, versionCode 중복, 서명 불일치) **0건**
- 사용자 안드로이드 앱 전부(현재 6개 이상)를 같은 파이프라인으로 관리

## MVP 범위
- GitHub Actions 재사용 워크플로: 빌드 → AAB 서명 → Play 업로드 → 트랙(내부·비공개·프로덕션) 지정 → 출시 노트 → 검토 제출
- 출시 전 가드:
  - 트랙별 광고 ID 규칙 (테스트 트랙 = 구글 테스트 ID, 프로덕션 = 실제 ID) 불일치 시 실패
  - versionCode가 Play에 이미 있는 값보다 큰지 확인
  - 패키지명·서명 키 지문이 기록과 같은지 확인
  - 권한·타깃 SDK 정책 경고
- 출시 노트: 커밋 메시지·변경 기록에서 한국어 출시 노트 초안 생성
- 비공개 테스트 추적: 테스터 수·참여 기간(14일 요건) 현황 리포트
- 앱 내 업데이트: Play In-App Updates 공통 모듈 (사용자 선호: 앱 안에서 업데이트)

## 기술 구조
- Google Play Developer API (edits: 업로드·트랙·출시 노트·커밋), 서비스 계정 키는 GitHub 비밀 저장소
- 검증된 공개 도구(fastlane supply 또는 Gradle Play Publisher)를 업로드 엔진으로 사용하고, 가드·노트·리포트를 그 위에 구현
- 앱별 설정: `release.yml`(패키지명, 트랙 정책, 광고 ID 파일 경로, 서명 지문)
- 알림: 31번 kit 텔레그램 알림 + 26번 운영 연동(출시 이벤트)

## 단계별 절차
| 단계 | 할 일 | 완료 기준 |
|---|---|---|
| 0. 인벤토리 | 사용자 안드로이드 앱 목록, 패키지명·서명·광고 설정·현재 트랙 정리 | 앱별 `release.yml` 초안 |
| 1. 서비스 계정 | Play Console API 접근 설정, 앱별 권한 부여 | 매매신호앱에서 트랙 조회 성공 |
| 2. 업로드 워크플로 | 태그 푸시 → AAB 빌드·업로드 → 비공개 테스트 트랙 | 매매신호앱 비공개 테스트 자동 업로드 |
| 3. 가드 | 광고 ID·versionCode·서명·패키지명 검사 | 일부러 틀린 설정 4종 모두 차단 |
| 4. 출시 노트 | 변경 기록 → 한국어 출시 노트 초안 | 사람 수정 없이 사용 가능한 비율 80% |
| 5. 승인 단계 | 프로덕션 출시는 GitHub 환경 승인(사람 1번 클릭) 후 진행 | 승인 없이는 프로덕션 업로드 불가 |
| 6. 테스트 추적 | 테스터 수·14일 진행 현황 주간 리포트 | 리포트 자동 발송 |
| 7. 전 앱 적용 | 31번 템플릿에 포함, 기존 앱에 PR로 적용 | 앱 6개 이상 적용 |

## 법·정책 주의사항
- 서비스 계정 권한은 최소(해당 앱 출시 관리만), 키는 비밀 저장소에만
- Google Play 정책(광고·권한·대상 연령) 검토는 자동 경고일 뿐 최종 판단은 사람
- 광고 정책: 개발자 본인이 실제 광고 클릭 금지 → 가드가 테스트 ID 사용을 강제하는 이유

## 리스크와 대응
- API·정책 변경 → 업로드 엔진은 공개 도구에 맡겨 유지보수 부담 최소화
- 첫 출시(스토어 등록정보·콘텐츠 등급·데이터 보안 양식)는 자동화 범위 밖 → 체크리스트 문서로 안내
- 자동 제출 실수 → 프로덕션은 반드시 사람 승인 단계

# 시너지 통합 묶음 (2026-10-16 제안 → 같은 날 사용자 지시로 7개 묶음 모두 통합 실행)

> 괄호 안 항목(4, 10, 17, 21-G2 연동, 32)은 연결만 하고 통합하지 않음.

채택 프로젝트 27개(병합분 제외) 중 **같은 입력 데이터·같은 엔진·같은 고객**을 공유하는 것끼리 묶었습니다.
"주"는 통합 후 중심이 될 프로젝트(그 세션이 통합 작업을 맡음)입니다.

통합 방식
- **완전 통합**: 한 레포·한 세션으로 합치고 나머지는 모듈이 됨
- **공유 엔진**: 각자 레포는 유지하되, 주 프로젝트가 공통 엔진을 패키지로 제공하고 나머지가 가져다 씀

## 묶음별 시너지
### G1 가계부 엔진 (6 + 12 + 23 + 28)
- 네 프로젝트 모두 **같은 카드 명세서**에서 시작. 지금은 파서·가맹점 분류를 네 번 만들 구조
- 12번(신용/체크카드 공제 전략)과 23번(카드 혜택)이 **같은 결정**(어떤 카드를 쓸까)을 따로 계산하는 문제 해소 → "혜택 + 절세" 한 번에 최적화
- 28번 경비 태그와 6번 구독 탐지가 같은 분류 결과 공유
- 결과: 월 1회 파일 넣기 → 리포트 4종 한 번에

### G2 문서 추출·청구 (18 + 24)
- 둘 다 "사진·PDF → 날짜·금액 추출 → 기한 알림" 구조. 추출·검수 화면·알림 엔진이 동일
- 24번이 필요로 하는 실손 약관 조건을 18번 보험 증권에서 바로 가져옴
- 18번 보증기간 데이터를 21번 판매글에 제공

### G3 투자 비서 (25 + 33 + 36 + 19)
- 25·33·36이 **같은 증권사 잔고**를 각자 조회하는 중복 제거, API 키 하나·호출 한도 하나로 관리
- 19·33이 **같은 DART 수집기** 사용
- 리밸런싱 매도 제안(25)에 양도세 영향(36)과 공시 위험(33)을 함께 표시 → 판단 품질 상승
- 17번 예금 만기·32번 연금 시뮬레이션은 이벤트·데이터로만 연결

### G4 지역 데이터 플랫폼 (1 + 29)
- 같은 지역 공공데이터 수집·좌표 변환
- 29번 반경 알림을 1번 사이트 방문자용 **유료·구독 기능**으로 열면 사이트 수익원 추가 (광고 + 뉴스레터 + 관심 지점 알림)
- 10번(42번 병합)의 지방행정 인허가 수집기와도 데이터 수집 코드 공유 가능

### G5 시세·중고 거래 (21 + 27, 4 엔진 공유)
- 공매로 싸게 산 물건(27)을 그대로 판매글(21)로 넘기는 흐름이 하나의 제품 안에서 완성
- 시세 엔진(신제품가 + 감가)을 4번 가격 알림 봇과 공유

### G6 판매 인프라 (39 + 7 + 30, 10 결제)
- 결제·정기결제·환불·주문 자동화·법적 고지를 한 번만 만들고 7·30·10이 사용
- 39번은 그렇게 검증된 코드를 상품으로 판매 → 만드는 비용이 곧 상품 개발

### G7 개발 기반 (31 + 26 + 16)
- 이미 서로 연결된 상태(34·35번 병합). 16번은 31번의 공휴일·영업일·공공 API 클라이언트를 외부 개발자용 API로 포장해 판매

## 통합 시 주의
- 이미 코드가 진행된 프로젝트(예: 1, 17, 6, 10 등)는 주 프로젝트 세션이 기존 레포 코드를 옮겨야 하므로, 통합 지시 시 "기존 레포를 모듈로 이전"을 명시
- 통합 후에는 `sessions.md`에서 흡수된 프로젝트를 "→ 주 프로젝트 세션"으로 표시
